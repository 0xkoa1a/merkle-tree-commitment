# 随机化 Merkle Tree Commitment 方案

本方案对一个**有序消息向量**生成固定大小的公开承诺。承诺方随后可以开封整个向量，也可以只开封指定位置；验证者根据此前保存的承诺检查消息、位置和数量是否一致。每个真实叶子独立使用 32 字节随机开封值，使低熵消息也能在明确的密码学假设下获得隐藏性。

具体哈希为手写 SHA3-256。树结构、消息编码、证明生成和验证均由本项目实现。实现、测试和基准均不调用现成哈希函数或 Merkle Tree 实现。测试使用公开的已知答案数据，与算法实现分开。

## 动机与设计取舍

原方案使用公开固定盐，攻击者可以枚举低熵消息并重新计算承诺；它也按值查找叶子，不能分别开封内容相同的不同位置。本方案使用每叶子独立随机值，并按索引开封，明确承诺对象是有序向量。

叶子、内部节点、占位叶和最终承诺分别使用不同类型前缀，防止同一哈希输入跨类型解释。真实叶子还包含向量数量、索引和消息长度，使编码可以唯一解析。域分隔的原则可参考 [RFC 9162 §2.1](https://www.rfc-editor.org/rfc/rfc9162.html#section-2.1)；本方案的随机化叶子及补齐规则是本作业的具体定义，并不声称实现了该 RFC 的完整协议。

非二次幂数量的向量补齐到下一二次幂，使用专门的占位叶。这样每个位置的路径长度一致，验证者可由数量和索引确定树形与左右方向。代价是额外占位节点；补齐数量小于真实数量的两倍，所以建树仍为线性复杂度。空向量被明确拒绝。

## 输入、输出与职责

- 输入：非空有序消息向量，数量记为 n。消息的数学对象是字节串；接口中的字符串按 UTF-8 编码，不做 Unicode 归一化。同编码的字符串和字节串表示同一消息。
- 公开输出：版本、n 和 32 字节承诺摘要。n 为公开信息，承诺方可以一次发布给多个验证者。
- 私有状态：所有消息、每个位置独立生成的 32 字节随机值，以及树的摘要层。由承诺方保管。
- 单项开封：消息、索引、该叶子的随机值及兄弟摘要路径。验证者不需要其他叶子的随机值。
- 完整开封：全部消息和全部随机值。它主动公开整个向量。

验证者必须事先保存可信的公开承诺，并明确自己要核对的位置。如果承诺和开封同时来自一个可任意改写它们的攻击者，验证成功只说明两者自洽，无法证明此前已经承诺该内容。承诺传递的真实性由应用负责。

## 方法

**共同编码。** H 表示本项目实现的 SHA3-256，输出 32 字节。U64 表示 8 字节大端无符号整数，数量和索引必须在其范围内，索引从 0 开始。所有摘要在树计算和证明中均使用原始字节，十六进制只用于展示。

真实叶子的哈希同时编码上下文、消息及其随机开封值。对索引 i 的消息 mᵢ 和独立随机值 rᵢ，叶子摘要为：

$$
L_i = H(\mathtt{00}\,\|\,U64(n)\,\|\,U64(i)\,\|\,U64(|m_i|)\,\|\,m_i\,\|\,r_i).
$$

这里 |mᵢ| 是消息字节数，rᵢ 固定为 32 字节。消息长度字段确定消息边界，随机值边界也就确定，因此不存在把部分消息重新解释为随机值的拼接歧义。

**树的构建。** 将真实叶子补齐到 N 个，其中 N 是不小于 n 的最小二次幂，深度 h = log₂N。对于 n ≤ i < N，占位叶为 H(02 ‖ U64(n) ‖ U64(i))。内部节点为 H(01 ‖ 左摘要 ‖ 右摘要)，其哈希输入固定 65 字节。最终树根记为 T，再计算公开承诺摘要 C = H(03 ‖ U64(n) ‖ T)。公开承诺是 (n, C)，数量同时包含在摘要中。

占位叶没有私有随机值，也不接受开封。它的类型前缀与真实叶子不同。内部节点的左右顺序固定，不能先排序再哈希。

**Commit。** 将输入规范化为字节串；每个叶子调用操作系统密码学随机源生成新的 32 字节 rᵢ；构造各层和 C；返回公开承诺与私有树状态。相同消息向量重新 Commit 会得到新的随机承诺，不能要求其根相同。

随机源通过 Python 标准库 `secrets.token_bytes` 使用操作系统随机性。它只负责生成随机字节，Merkle 和哈希计算都走本项目代码。正式承诺接口不接受调用方设置固定盐或伪随机种子；在两个承诺之间也重新生成所有 rᵢ。

**单项 Open。** 根据索引 i 获取 mᵢ、rᵢ，从叶到根收集每层兄弟摘要。证明只包含索引、rᵢ 和这 h 个摘要，不重复发送当前节点摘要或父摘要。

**单项 Verify。** 验证者传入保存的承诺、期望索引、消息和证明。先检查编码版本、字段范围、索引一致性、i < n、摘要大小及路径长度恰为 h。然后重算真实叶子，根据索引每一位确定左右位置，逐层重算 T，最后重算 C 并与保存值比较。通过返回 True；不匹配或畸形证明返回 False。独立解析器对畸形编码抛出 ValueError。

**完整 Open 与 Verify。** 承诺方公开全部消息和 rᵢ。验证者检查数量和字段长度，按相同规则重建树并比较 C。这个入口满足对整个消息向量的传统承诺与开封语义，单项路径是部分开封功能。

**序列化格式。** 版本固定为 1；下表各字段严格按顺序编码。解析器拒绝尾随字节、截断、未知版本和不一致的长度，证明最多 64 层。

| 对象 | 编码内容 | 实际大小 |
| --- | --- | --- |
| 公开承诺 | 1 B 版本、8 B 数量、32 B 摘要 | 41 B |
| 单项证明 | 1 B 版本、8 B 索引、32 B 随机值、2 B 大端路径层数、每层 32 B 兄弟摘要 | 43 + 32h B |
| 完整开封 | 1 B 版本、8 B 数量，每个消息依次编码 8 B 长度、消息、32 B 随机值 | 9 + Σ(40 + 消息字节数) B |

单项消息是 Verify 的单独输入，**不计入单项证明大小**。若需要统计整个单项开封消息，必须再加消息内容及其应用层长度编码。算法版本由协议固定；要采用另一版本，需要另行定义并解析，当前实现拒绝未知版本。

## 安全性分析

### Binding：一个承诺不能开出不同的消息

安全目标有两种表达：攻击者不能为同一个公开承诺给出两个被接受的完整开封，其中消息向量不同；也不能为同一承诺和同一索引，给出两个被接受的单项开封，其中消息不同。随机值只是开封信息的一部分，真正需要绑定的是消息向量及其位置。

这个结论以 **SHA3-256 抗碰撞**为假设，适用于恶意承诺方，可以允许它任意选择随机值。编码的唯一解析和节点域分隔是归约的前提。

- 完整开封的向量数量不同：无法同时匹配公开数量；即使忽略这个外层检查，在摘要中改变 n 而保持 C 不变也会构成不同哈希输入的碰撞。
- 数量相同而某个消息不同：其真实叶子输入不同。若对应叶子摘要相同，已经得到 H 的碰撞；否则沿这条路径向上，在两个不同子节点对第一次产生相同父摘要的位置得到碰撞。如果树根不同而 C 相同，则最终承诺哈希发生碰撞。
- 两个同索引的单项开封均被接受：两条路径最终匹配同一 C。若它们的消息不同，其叶子输入必然不同。逐层应用同样的“输入不同、输出相同”推理，至少可以提取一次碰撞。路径长短、数量及左右位置由验证规则固定，不能通过重新解释树形绕过这个推理。

因此，成功破坏上述 binding 可以构造 SHA3-256 碰撞。对于 256 bit 摘要，通用碰撞攻击的工作量尺度是约 2¹²⁸；这不是对实现无漏洞的保证。重排、删增消息及跨位置证明都在绑定目标内。类型前缀使真实叶子、占位叶、内部节点和最终承诺输入互不混淆。

### Hiding：承诺不暴露未开封消息

**仅有抗碰撞或抗原像性不能推出 hiding。** 本方案在随机预言机模型中分析 H：攻击者可以查询任意哈希输入，哈希在不同输入上产生独立均匀的 256 bit 输出。使用具体 SHA3-256 是对此模型的工程实例化，不能把模型证明写成对 SHA3 的无条件定理。

基本 hiding 游戏让攻击者选择两个具有相同公开数量的消息向量，挑战者随机选择其中一个，独立生成所有 rᵢ 并给出承诺。攻击者根据承诺猜测选择了哪一组，超出随机猜测的优势应可忽略。数量公开，所以不比较不同 n 的向量。

在攻击者没有查询某个真实叶子的完整输入之前，该叶子的摘要可视为独立随机值，其分布不依赖消息内容。这些摘要再经固定树形计算得到承诺，两个挑战向量产生的公开视图具有相同分布。使两个视图出现可区分信息的关键事件，是攻击者猜中了某个未知 rᵢ 并查询对应叶子输入；即使消息只有一个数字，也仍需猜中这个 256 bit 随机值。

设 q 为攻击者的哈希查询次数，n 为真实叶子数。对两组挑战实验使用保守的联合界，查询命中隐藏叶子输入的概率至多约 2nq / 2²⁵⁶。在未命中事件下，可以耦合两个实验的随机摘要，使公开视图相同。因此，多项式数量的叶子与查询下，区分优势可忽略。该界用于随机预言机模型和理想的独立均匀随机值；它不声称具体实现具有可实测的“256 bit 整体安全强度”。Binding 的通用强度仍受碰撞界限制。

**部分开封的边界。** 对一个预先固定的开封位置集合，考虑两组在这些位置上消息相同的挑战向量。被开封消息、其随机值和认证路径均可公开；其他位置仍使用独立的未知随机值，前述查询命中论证可应用于未开封位置。兄弟摘要公开不等于其随机值公开，开封某个 rᵢ 也无法用于计算其他位置的真实叶子输入。

这给出本作业范围内的固定集合部分开封论证。实现允许按需多次开封，但本文不声称证明了任意相关消息分布下的一般自适应选择性开封安全。若已公开消息与隐藏消息存在外部相关性，攻击者仍可能从这些公开信息推断隐藏内容；承诺不能消除消息自身的相关性。

公开数量和索引、开封后的消息及其长度均不在隐藏目标内。运行时间、消息内存、进程调试、随机源失效、私有状态泄露和侧信道也不由上述协议证明覆盖。完整开封主动公开全部内容，之后不再声称这些消息隐藏。

### 假设与实验的关系

独立的高熵随机值必须在每次承诺中重新生成；不能公开未开封随机值，也不能把固定种子或低熵字符串当作随机值。SHA3-256 的通用安全工作量参考 [FIPS 202](https://csrc.nist.gov/pubs/fips/202/final)，本项目按该规范实现算法，但没有获得 NIST 认证。

猜测实验分为三种真实信息条件：公开固定盐的旧方案可枚举恢复；只有 4 bit 有效熵的随机值也可枚举恢复；新方案开封一个叶子后，使用已开随机值或小随机值字典不能在本次有限实验中恢复其他叶子。前两项是反例，最后一项是演示。新方案的 hiding 结论由上述模型和随机性假设支撑，不能由“没猜中”证明。

## SHA3-256 的具体实现

SHA3-256 采用 Keccak-f[1600] 的 24 轮置换，状态为 25 个 64 bit lane。吸收率为 1088 bit（136 B），容量为 512 bit，输出为 256 bit。每轮依次执行 θ、ρ、π、χ、ι；Python 整数操作通过 64 bit 掩码限制，lane 按小端字节序读写。

字节消息使用 SHA-3 后缀 0x06，并在最后填充字节设置 0x80。当消息长度模 136 为 135 时，两者合并为 0x86；消息恰好占满一块时增加新填充块。SHA3-256 与通常称为 Keccak-256 的实例后缀不同，本实现采用 FIPS 202 的 SHA3-256。

一次哈希需要的置换次数是消息字节数除以 136 的整数商再加 1。真实叶子的哈希输入有 57 B 固定开销，内部节点输入 65 B，最终承诺输入 41 B。因此“哈希调用次数”与“Keccak 置换次数”要区分，长消息会增加单次叶子哈希的成本。

## 验证与性能

固定答案来自 [NIST CAVP 的 SHA-3 字节测试向量](https://csrc.nist.gov/CSRC/media/Projects/Cryptographic-Algorithm-Validation-Program/documents/sha3/sha-3bytetestvectors.zip)：全部 137 条 ShortMsg（0–136 B）以及 273、410、4109 B 三条 LongMsg，共 140 条；另有 abc 固定示例。来源、消息及期望摘要均保存在 tests/data/sha3_vectors.json，测试运行时不调用外部哈希实现。

正式测试覆盖非二次幂向量、单叶子、重复消息、空消息、Unicode、独立递归规格重算、消息/随机值/兄弟摘要篡改、位置/数量/根替换、证明长短及顺序、完整开封重排和删项、序列化往返、截断、尾随字节和非法类型。

完整基准记录不同 n、消息长度和哈希输入长度，测量建树、证明生成、证明序列化、单项验证和完整验证；另测 Python 分配峰值。实际字节大小直接由序列化结果取得。每项一次预热、默认五组样本，保留每组原始计时，并报告均值与标准差。

补齐叶数为 N 时，建树实际调用哈希 2N 次，包括 N 个真实/占位叶、N−1 个内部节点和一次最终数量绑定。单项验证调用 h+2 次哈希。建树和完整验证为 O(n)，单项证明生成及验证为 O(log n)；处理消息内容的成本还与总字节数相关，私有状态存储为 O(n + 总消息字节数)。

实测表格、环境及结果解释见 [性能与验证结果](../results/性能与验证结果.md)，原始样本见 `results/results.json`，执行输出见 `results/run.log`（路径相对于仓库根目录）。算法测试和有限对抗测试帮助发现实现错误；它们不替代安全性归约。
