# 实验结果

实验包含四个单叶演示、四个树级实验和三个性能实验，图和分析集中在 [方案设计](../docs/方案设计.md#密码分布实验)。原始记录保存在 [distribution.json](distribution.json)（文件过大，git-ignored）与 [performance.json](performance.json)，后者保留每个参数点的九组计时。

叶摘要在消息或 nonce 改一位后，平均改变约 128 个输出位；低熵消息类别的逐位频率差围绕零波动。未知 nonce 的枚举空间按位数指数增加，首次投影碰撞则按输出空间的平方根增长。这些规律分别对应随机化输入的混合、Hiding 的猜测成本，以及 Binding 的碰撞成本。

A′（原 E）中，树上篡改每层只改变一个祖先节点，路径摘要的汉明距离维持在约 128 位。树的深度决定传播和验证步骤，256 位输出宽度决定哈希的密码学门槛。

B′ 实际打开目标的邻居，观察公开 C 和邻居证明中目标叶摘要的类别频率差。C′ 打开全部其他叶，分别执行走根恢复与直接叶匹配；二者恢复同一候选，实际哈希调用数之比为 h+2。D′ 为每个短承诺碰撞保留两份完整开封，并检验两份都被弱化规则接受、第二份被正式 256 位规则拒绝。这些树级实验把 nonce 的未知空间、证明的公开材料和 Binding 的冲突开封连接起来。

树规模从 1024 增到 1025 时，建树由 1.196 s 增到 2.435 s；4096 增到 4097 时由 4.780 s 增到 9.592 s。这是补齐容量翻倍的阶跃。4096 叶的 open 约为 3.93 μs，verify 约为 8.21 ms，展示已有树上收集路径与重新执行哈希的成本差异。

消息长度从 78 增到 79 B 时，32 叶建树由 36.98 ms 增到 56.44 ms，单项验证由 4.01 ms 增到 4.62 ms。叶编码的 57 B 开销使这一点跨过 SHA3 的 136 B 分块边界；建树处理全部叶，因此增幅比只重算一个叶的单项验证更大。

运行及从 JSON 重绘的命令见 [README](../README.md#测试与实验)。C 后端和 Multiproof 的扩展入口位于实验脚本的 TODO 注释中。
